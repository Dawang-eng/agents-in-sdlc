使用 GitHub Copilot 智能体模式后，它会自主探索代码库、提出更改、编辑文件并运行命令。由于 Copilot 会在本地计算机上实时工作，VS Code 中的 Copilot Chat 会持续显示工具调用和文件编辑。可以内联审查每项差异、接受或拒绝单项更改，并通过后续提示引导对话，在不离开编辑器的情况下完善或扩展当前工作。

本练习将：

- 实时监控无障碍智能体的工作。
- 审查并接受建议的文件编辑。
- 在会话进行期间引导智能体，在高对比度模式之外添加浅色模式切换开关。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍自定义智能体正在实现高对比度模式。工作进行期间，设计团队又提出一项要求：希望为觉得默认主题太暗的用户添加浅色模式切换开关。无需从头开始新对话，可以直接引导现有会话扩展工作内容。

## 监控 Copilot 的进度

Copilot Chat 视图会显示智能体执行的每个步骤，包括探索的文件、运行的命令和提出的编辑。每项文件编辑都会以内联方式显示在聊天中，附带差异以及 **Keep**/**Undo** 控件。

1. 返回练习 4 中使用的 Copilot Chat 视图。
2. 智能体工作时，滚动聊天内容，查看每个工具调用的结果。你会看到文件读取、文件编辑，以及它请求运行的终端命令。
3. 智能体提出文件编辑时，差异会以内联方式显示：
    - 选择 **Keep** 接受更改。
    - 选择 **Undo** 撤销更改，让智能体重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在本次会话中修改的完整文件列表。

> [!NOTE]
> 如果工具调用请求权限（例如需要运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你信任的命令。

5. 等待智能体完成高对比度模式的实现。完成时应会看到总结更改内容的最终消息。

## 引导智能体添加浅色模式

高对比度模式完成后，在同一对话中继续添加浅色模式切换开关。由于继续使用同一聊天会话，智能体会保留之前工作的上下文，包括修改的组件、使用的样式方案和设置的本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得很好！现在请在高对比度开关旁添加浅色模式开关。浅色模式应采用相同模式：使用本地存储保留设置，并且可以在 UI 的同一区域中访问。用户应能分别启用高对比度模式和浅色模式。
    ```

2. 智能体会从之前的进度继续工作，探索已完成的更改并提出浅色模式的新增内容。
3. 与高对比度模式一样，逐项审查新的编辑，并在每个差异上选择 **Keep** 或 **Undo**。
4. 如果智能体采取了不符合预期的方向（例如尝试以不喜欢的方式重构开关 UI），可以选择聊天输入框旁边的 **Stop** 按钮停止任务，然后发送更明确的后续消息。

> [!TIP]
> 引导正在进行的会话比从头开始更快。可以使用后续提示要求调整（“简化 CSS，改用 CSS 变量，不要重复选择器”）、纠正方向（“不要添加第三个开关，应将浅色模式整合到现有设置面板中”）或扩展范围（“为两个开关都添加键盘快捷键”）。

## 审查工作集

提交工作前，快速检查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 审查更改文件列表。应能看到 Astro 组件、样式以及相关测试的更新。
3. 打开几个已更改的文件并查看差异。确认其中体现了自定义智能体要求的无障碍模式，包括 ARIA 属性、键盘导航、语义化 HTML 和本地存储。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结与后续步骤

本课使用 Copilot Chat 智能体模式监控并引导正在进行的会话：逐项审查文件编辑、接受或拒绝更改，并通过后续提示扩展工作且保留上下文。

本课介绍了以下概念：

- 实时监控智能体的工作。
- 接受或拒绝单项文件编辑。
- 通过后续提示引导正在进行的会话。

在[下一课][next-lesson]中，将把无障碍功能作为拉取请求发布，并审查本实验中本地自定义智能体生成的更改。
