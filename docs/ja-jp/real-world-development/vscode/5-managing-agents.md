GitHub Copilot をエージェント モードにすると、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat で作業状況をリアルタイムに確認できます。すべてのツール呼び出しやファイルの編集が表示されるため、差分を確認しながら個々の変更を採用または元に戻し、追加のプロンプトで会話を調整したり作業を拡張したりできます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムに監視する。
- 提案されたファイル変更をレビューして採用する。
- 実行中のセッションに指示を送り、ハイコントラスト モードに加えてライト モードの切り替えも追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイコントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者向けに、ライト モードも追加したいとのことです。新しい会話を始める代わりに、既存のセッションに指示を送り、作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが調べたファイル、実行したコマンド、提案した変更を順に確認できます。各ファイルの編集は差分と **Keep** / **Undo** ボタン付きでチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドなどが表示されます。
3. エージェントがファイルの変更を提案すると、差分がチャットに表示されます。
   - **Keep** を選ぶと変更を採用します。
   - **Undo** を選ぶと変更を元に戻し、エージェントに別の方法を試させます。
4. チャット上部の **Files changed** を開き、セッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ツールの実行に許可が必要な場合 (ターミナル コマンドなど)、エージェントは一時停止し **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラスト モードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライト モードを追加するよう依頼する

ハイコントラスト モードの準備ができたら、同じ会話でライト モードの切り替えを追加します。同じチャットを続けることで、エージェントは前の作業のコンテキスト、変更したコンポーネント、スタイルの方針、local storage の使い方を引き継ぎます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは、既存の変更を調べ、ライト モードを追加する変更を提案します。
3. ハイコントラスト モードと同様に、提案された各変更を確認して **Keep** または **Undo** を選びます。
4. エージェントが望まない方向に進んだ場合 (たとえば、切り替え UI を意図しない形で再構成しようとした場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送ります。

> [!TIP]
> 新しいセッションを始めるより、作業中のセッションに追加の指示を送る方が効率的です。「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」などの修正、「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを統合する」などの方向修正、「2 つの切り替えにキーボード ショートカットも追加する」などの範囲拡張を依頼できます。

## 作業内容をレビューする

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. エージェントが変更したファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが表示されます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ指針が反映されていることを確認します。たとえば ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存などです。
4. 問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードで、進行中のセッションを監視して調整しました。ファイル変更を確認し、採用または元に戻し、会話のコンテキストを保ったまま追加の指示を送って作業を拡張しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムに監視しました。
- 個々のファイル変更を採用または元に戻しました。
- 追加の指示を送って、作業中のセッションを調整しました。
